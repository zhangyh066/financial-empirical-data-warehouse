# 数据仓库从 0 到精通：像开发者一样理解 EFDW

> 本教程基于你文件夹中的 `enterprise-financial-data-warehouse` 项目（企业财务实证数据仓库系统），目标是从零基础开始，让你像自己开发了这个项目一样理解它。

---

## 第一部分：数据仓库是什么？为什么需要它？

### 1.1 没有数据仓库时，财务实证研究是怎么做的？

假设你正在写一篇公司金融实证论文，研究"现金持有对企业绩效的影响"。你需要：

1. 从 **CSMAR** 下载公司基本信息、资产负债表、利润表、现金流量表
2. 从 **Wind** 下载股权市值数据
3. 把多个 Excel 打开，用 VLOOKUP 或者 Stata `merge` 拼在一起
4. 计算 ROA、ROE、Lev、流动比率、周转率、营收增长率等指标
5. 生成滞后项 `L.roa`、`L2.roa`、`F.roa`
6. 导出 `.dta` 文件到 Stata 跑回归

**痛点：**
- 多表合并容易出错（股票代码前导零丢失、公司名称变更导致匹配不上）
- 财务指标计算逻辑散落在不同 do 文件里，改了一个地方忘了另一个地方
- 数据来源不统一，复现困难
- 每次更新数据都要重新跑一遍完整流程

### 1.2 数据仓库解决什么问题？

数据仓库（Data Warehouse）的核心思想是：**把数据分层管理，每一层只做一件事，层层递进，最终输出可直接用于分析的数据集。**

就像工厂的生产线：
- 原材料 → 粗加工 → 精加工 → 成品 → 出货
- 原始数据 → 贴源层 → 明细层 → 服务层 → 应用层

### 1.3 这个项目的定位

这是一个**企业财务实证数据仓库系统（Enterprise Financial Data Warehouse, EFDW）**，专门为财务实证研究设计：
- 技术栈轻量：Python + DuckDB + SQL
- 零配置：一个 `.db` 文件就是整个数据库
- 学术友好：自动计算盈利/成长/偿债/营运/现金流五大类指标 + 杜邦分解 + 多期滞后项
- Stata/R 友好：一键导出 `.dta` 和 `.csv`

## 第二部分：四层架构——这是数据仓库的灵魂

这个项目采用了经典的四层架构：

```
┌─────────────────────────────────────────────────────────┐
│  ODS  贴源层  →  原始 CSMAR 财务三表，只读不修改          │
│  DWD  明细层  →  字段翻译、公司维度消歧、年报过滤          │
│  DWS  服务层  →  企业-年度财务指标面板（含滞后项/杜邦）    │
│  ADS  应用层  →  行业-年度聚合集市（可直接出图出表）       │
└─────────────────────────────────────────────────────────┘
```

### 2.1 ODS（Operational Data Store）贴源层

**作用：** 原样存放从 CSMAR/Wind 下载的数据，不做任何修改。相当于"原始档案室"。

本项目中的 ODS 表：
- `ods.company_info`：公司基本信息（代码、名称、上市日期、行业代码）
- `ods.financial_raw`：财务三表明细（17 个科目，覆盖资产负债表/利润表/现金流量表/市值）
- `ods.company_names_raw`：企业曾用名历史变更记录

**为什么单独一层？** 保证原始数据可溯源。任何时候发现下游数据有问题，都可以回到 ODS 层核对。

### 2.2 DWD（Data Warehouse Detail）明细层

**作用：** 对 ODS 数据进行清洗、标准化、维度建模。三件事：

1. **字段翻译**：把 CSMAR 的字段代码（`F010101A` 等）翻译成学术规范字段名（`assets`）
2. **维度建模**：构建公司维度表 `dim_company`、曾用名维度表 `dim_company_names`
3. **数据过滤**：只保留 12 月 31 日的年报数据（实证论文惯例）

### 2.3 DWS（Data Warehouse Service）服务层

**作用：** 把多张明细表拼成一张**企业-年度面板宽表**，并计算所有财务指标。这是整个数仓最核心的层。

DWS 层自动计算的变量（按五大能力分组）：

| 分类 | 变量名 | 公式 | 说明 |
|------|--------|------|------|
| 规模/市场 | `firm_size` | `ln(assets)` | 企业规模 |
| 规模/市场 | `leverage` | `debt / assets` | 资产负债率 |
| 规模/市场 | `tobin_q` | `(equity_mv + debt) / assets` | 托宾 Q |
| 盈利能力 | `roa` | `net_income / assets` | 总资产收益率 |
| 盈利能力 | `roe` | `net_income / equity` | 净资产收益率 |
| 盈利能力 | `gross_margin` | `(revenue - cost) / revenue` | 销售毛利率 |
| 成长性 | `revenue_growth` | `(revₜ - revₜ₋₁) / revₜ₋₁` | 营收增长率 |
| 成长性 | `asset_growth` | 同上 | 总资产增长率 |
| 偿债能力 | `current_ratio` | `流动资产 / 流动负债` | 流动比率 |
| 偿债能力 | `quick_ratio` | `(流动资产 - 存货) / 流动负债` | 速动比率 |
| 偿债能力 | `interest_coverage` | `(营业利润+利息费用) / 利息费用` | 利息保障倍数 |
| 营运能力 | `total_asset_turnover` | `revenue / assets` | 总资产周转率 |
| 营运能力 | `cash_conversion_cycle` | `DIO + DSO - DPO` | 现金转换周期 |
| 风险预警 | `altman_z` | `1.2X₁+1.4X₂+3.3X₃+0.6X₄+X₅` | Altman Z 财务困境预警（非金融企业） |
| 杜邦分解 | `equity_multiplier` | `assets / equity` | 权益乘数 |
| 杜邦分解 | `dupont_roe` | `净利率 × 周转率 × 权益乘数` | 杜邦验证 ROE |
| 时序项 | `lag_roa` / `lag2_roa` | `LAG(roa, 1/2) OVER (stkcd, year)` | 滞后一/两期 |
| 时序项 | `lead_roa` | `LEAD(roa, 1)` | 超前一期 |

### 2.4 ADS（Application Data Store）应用层

**作用：** 面向具体分析场景的高度聚合数据，直接服务论文出图出表。

本项目中 ADS 层是数据库中真实存在的表（不再是导出文件）：
- `ads.industry_year_stats`：行业 × 年度的均值聚合（行业均值 ROA/Lev/增长率等、行业总营收）
- `ads.market_year_overview`：全市场年度概览（总资产的规模、总营收、平均 ROE 等）
- `ads.data_quality_report`：财务勾稽关系校验的违规明细长表（资产=负债+权益、流动资产构成、科目非负等 10 项检查），是接入真实 CSMAR 数据时的数据质量闸门

同时，按论文需求导出的 `.dta` / `.csv` 文件也属于 ADS 层的交付物。

### 3.4 第四步：DWD 清洗

文件：`src/sql/dwd_cleaning.sql`

这是 SQL 脚本，核心操作：

#### 3.4.1 构建公司维度表

```sql
CREATE TABLE dwd.dim_company AS
SELECT
    TRIM(Stkcd) AS stkcd,           -- 去除空格
    TRIM(Comnam) AS company_name,   -- 公司名称
    CAST(Listdt AS DATE) AS list_date,
    EXTRACT(YEAR FROM CAST(Listdt AS DATE))::INTEGER AS list_year,
    TRIM(Indcd) AS industry_code,
    CASE SUBSTRING(TRIM(Indcd), 1, 1)  -- 证监会 2012 行业门类映射
        WHEN 'J' THEN '金融业'
        WHEN 'K' THEN '房地产业'
        WHEN 'C' THEN '制造业'
        ...
    END AS industry_category
FROM ods.company_info;
```

> 注意：`list_year` 是为了支持"剔除上市不足一年新股"的实证样本筛选。

#### 3.4.2 构建财务明细事实表

```sql
CREATE TABLE dwd.fact_financial AS
SELECT
    TRIM(Stkcd) AS stkcd,
    EXTRACT(YEAR FROM CAST(Accper AS DATE))::INTEGER AS year,
    -- 资产负债表
    F010101A AS assets,          -- 总资产
    F010201A AS debt,            -- 总负债
    F010301A AS equity,          -- 所有者权益
    F010701A AS current_assets,  -- 流动资产
    ...
    -- 利润表
    F020101A AS revenue,         -- 营业总收入
    F030101A AS net_income,      -- 净利润
    -- 现金流量表
    F040101A AS ocf              -- 经营现金流净额
FROM ods.financial_raw
WHERE EXTRACT(MONTH FROM CAST(Accper AS DATE)) = 12;  -- 只保留年报
```

#### 3.4.3 构建曾用名维度表

```sql
CREATE TABLE dwd.dim_company_names AS
SELECT
    TRIM(Stkcd) AS stkcd,
    TRIM(Comnam) AS company_name_history,
    CAST(BeginDate AS DATE) AS begin_date,
    CAST(EndDate AS DATE) AS end_date
FROM ods.company_names_raw;
```

### 3.5 第五步：DWS 财务指标面板

文件：`src/sql/dws_panel.sql`

这是最关键的一步，把财务三表拼成一张宽表，并计算所有指标。

```sql
WITH base_panel AS (
    -- 1. 拼表：财务明细 + 公司维度
    SELECT f.stkcd, c.company_name, c.industry_category, c.list_year,
           f.year, f.assets, f.debt, f.equity, f.revenue, f.net_income, ...
    FROM dwd.fact_financial f
    LEFT JOIN dwd.dim_company c ON f.stkcd = c.stkcd
),
ratios AS (
    -- 2. 五大能力指标 + 杜邦三因子
    SELECT *,
        net_income / assets AS roa,
        net_income / NULLIF(equity, 0) AS roe,
        current_assets / NULLIF(current_liabilities, 0) AS current_ratio,
        ...
        assets / NULLIF(equity, 0) AS equity_multiplier
    FROM base_panel
),
growth AS (
    -- 3. 成长性指标（窗口函数取上期值）
    SELECT *,
        (revenue - LAG(revenue, 1) OVER w) / NULLIF(LAG(revenue, 1) OVER w, 0) AS revenue_growth
    FROM ratios
    WINDOW w AS (PARTITION BY stkcd ORDER BY year)
)
-- 4. 多期滞后项 / 超前项
SELECT *,
    LAG(roa, 1) OVER w AS lag_roa,
    LAG(roa, 2) OVER w AS lag2_roa,
    LEAD(roa, 1) OVER w AS lead_roa
FROM growth
WINDOW w AS (PARTITION BY stkcd ORDER BY year);
```

**SQL 核心知识点：**
- `LEFT JOIN`：左连接，保留左边表的所有行，右边没有匹配的就补 NULL
- `NULLIF(x, 0)`：除数为零时返回 NULL 而不是报错，保证指标可计算
- `LAG(roa, 1) OVER (PARTITION BY stkcd ORDER BY year)`：窗口函数，按公司分区、按年份排序，取上一期的 ROA（Stata 的 `L.roa`）
- `LAG(roa, 2)`：滞后两期（Stata 的 `L2.roa`），"多期滞后项"的关键
- `LEAD(roa, 1)`：超前一期（Stata 的 `F.roa`）
- 杜邦恒等式：`净利率 × 总资产周转率 × 权益乘数 = ROE`（数仓内置 `dupont_roe` 校验字段）

### 3.6 第六步：ADS 聚合集市

### 4.2 核心设计亮点

#### 4.2.1 动态样本筛选（`apply_sample_filters`）

```python
def apply_sample_filters(df, year_min, year_max, exclude_financial, exclude_newly_listed):
    df = df[(df["year"] >= year_min) & (df["year"] <= year_max)]
    if exclude_financial:
        df = df[df["industry_category"] != "金融业"]
    if exclude_newly_listed:
        df = df[df["year"] > df["list_year"]]   # 剔除上市不足一年的新股
    return df
```

**为什么重要？** 实证论文的样本清洗标准（剔除金融业、剔除 ST、剔除新股）直接决定回归结果，把这些逻辑下沉到数仓服务层，保证每次取数口径一致。

#### 4.2.2 缩尾处理（Winsorize）

```python
def winsorize(series: pd.Series, pct: float) -> pd.Series:
    if pct <= 0:
        return series
    lo = series.quantile(pct)
    hi = series.quantile(1 - pct)
    return series.clip(lower=lo, upper=hi)
```

**什么是缩尾？**
学术研究中，为了避免极端值影响回归结果，通常把变量的尾部 1% 或 5% 替换为对应分位数的值。

#### 4.2.3 公司名称智能消歧（4 级匹配）

```python
# 1. 当前名称精确匹配
# 2. 历史名称精确匹配
# 3. 子串匹配
# 4. Jaro-Winkler 模糊匹配
```

**为什么需要这个？**
你的外部数据可能写的是"深发展"，但标准库里是"平安银行"；或者写的是"万科集团"，标准是"万科 A"。这个接口可以自动对齐——这是中国上市公司实证研究最头疼的问题之一。

## 第八部分：关键代码知识点清单

### 8.1 DuckDB

DuckDB 是一个**嵌入式分析型数据库**，特点是：
- 一个文件就是一个数据库（类似 SQLite）
- 列式存储，查询快（千万级毫秒响应）
- 支持标准 SQL 和窗口函数
- 可以直接读取 CSV/Parquet

### 8.2 SQL 窗口函数

```sql
-- 滞后一期 / 两期
LAG(roa, 1) OVER (PARTITION BY stkcd ORDER BY year)
LAG(roa, 2) OVER (PARTITION BY stkcd ORDER BY year)

-- 超前一期
LEAD(roa, 1) OVER (PARTITION BY stkcd ORDER BY year)

-- 行业年度均值
AVG(roa) OVER (PARTITION BY industry_category, year)
```

### 8.3 FastAPI

FastAPI 是 Python 的高性能 Web 框架，用于构建 API：

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/api/stats")
def get_stats():
    return {"n_firms": 6}
```

### 8.4 Pandas 导出 Stata

```python
df.to_stata("data.dta", write_index=False, version=118)
```

## 第十部分：常见问题

### Q1: 股票代码前导零丢失了怎么办？

在 `import_raw.py` 中，以下列名会自动转为 VARCHAR：
```python
VARCHAR_FORCE_COLUMNS = {
    "stkcd", "stockcode", "stock_code", "code", "ticker",
    ...
}
```

如果你的列名不在这个列表里，可以在导入时指定：
```bash
python src/etl/import_raw.py --file data/raw/mydata.csv --table ods.mydata --varchar my_code_col
```

### Q2: 如何添加新的财务指标？

在 `src/sql/dws_panel.sql` 的 `ratios` CTE 中添加：
```sql
rd / revenue AS rd_intensity,
```

### Q3: 如何扩展更多公司/更多年份？

替换 `data/raw/` 下的文件为你的真实数据，然后重新运行 Pipeline。

### Q4: 前端连不上后端？

检查 `frontend/app.js` 第 12 行的 API 地址是否和启动后端的端口一致：
```javascript
const API = 'http://127.0.0.1:8000';
```
